# D17 — ICM travels in the repo: the contract and the procedure are vendored

**Date:** 2026-07-28 · **Status:** Committed
**Relates to:** [D2](2026-07-28-D02-adapters-target-harnesses.md),
[D8](2026-07-28-D08-split-store.md),
[D13](2026-07-28-D13-mechanical-work-is-scripted.md)

## Context

Two separate dependencies on ICM had no home in the repo:

1. **The definition.** `scan::detect_icm` already implements the L0/L1 fallback
   chains — `AGENTS.md` → `CLAUDE.md`, and root `CONTEXT.md` → routing section →
   `README.md`. Until now their only written justification was a doc comment in
   Rust and a table in a plan document living in a *different* repository.
2. **The procedure.** M10's new-project flow is *interview → `icm-architect` →
   `git init` → private remote*, which assumed a skill installed at
   `~/.claude/skills/icm-architect` on one machine, under one harness.

## Decision

Both move into `config/`, the committed and synced half of the split store.

- **`config/contracts/icm.md`** — canonical for what GIT HUD detects as an ICM
  workspace. The Rust detector implements it; if they disagree, the code is
  wrong.
- **`config/skills/icm-architect/`** — the upstream procedure, vendored verbatim
  with its `LICENSE`, plus one GIT HUD-owned `CONTEXT.md` carrying the
  harness-neutral invocation notes and the update path.

## Rationale

**A harness-local dependency is not portable, and portability is a committed
constraint.** D2 makes GIT HUD adapter-agnostic on purpose. A flow that only
works when one specific harness happens to have one specific skill installed
contradicts that, and fails silently — the step does not error, it simply
vanishes, which is the worst available failure mode.

**Installing it elsewhere relocates the lock-in rather than removing it.**
Dropping the skill into `.claude/skills/` reproduces the same problem for the
next adapter. The vendored copy is harness-neutral by construction: `SKILL.md`
below its frontmatter is plain markdown any capable agent can execute by
reading, and the frontmatter is registration metadata, not a dependency.

**The contract is needed now, not at M10.** M1 shipped `detect_icm` this same
day. A definition that lives only as a comment in the code it justifies is not a
contract — it is a rationalisation, and it cannot be cited by the next adapter,
the next machine, or a human arguing with the badge.

**One canonical home is preserved.** `contracts/icm.md` owns the definition;
`scan/mod.rs` cites it. Without this decision the definition had two homes — the
Rust and an external plan — which the repo's own rules forbid.

## Why this is not a principle 1 violation

Principle 1 says GIT HUD carries **no project workflow knowledge**, and this
looks like an exception. It is not, and the distinction should not be
re-litigated later:

Principle 1 forbids GIT HUD from knowing *another project's* rules — how that
repo builds, tests, or ships. ICM is not another project's rule. It is **GIT
HUD's own contract for how it reads and births projects**, exactly like
`contracts/milestones.md`, which GIT HUD already parses out of arbitrary repos
without anyone calling it a violation. Owning the format you read is the
opposite of absorbing someone else's workflow.

The test: GIT HUD never tells a project *what its stages should be*. It only
recognises whether the project can orient an agent, and offers a procedure for
building one if not.

## Licensing

Upstream `icm-architect` is **MIT, © 2026 Jake Van Clief** — the same author as
the ICM paper this project's method already cites. MIT permits vendoring,
modification, and redistribution provided the copyright notice and permission
notice travel with the copy. `LICENSE` is therefore vendored alongside and must
never be removed. This is named explicitly rather than assumed, because
vendoring third-party work into a repo without recording its terms is how
licensing problems start.

## Consequences

- Upstream is **verbatim and must stay that way**; the only GIT HUD-owned file
  in that directory is `CONTEXT.md`. Local edits would fork the method silently.
- `.upstream-manifest.txt` records a `sha256sum` per file, so drift from
  upstream is detectable with `sha256sum -c` rather than by eye.
- **M10's flow now points at the vendored copy**, not at whatever happens to be
  installed.
- `scan/mod.rs` cites `config/contracts/icm.md` as its source of truth.
- Changing detection is a versioned breaking change touching the contract and
  the Rust together.
- The two ICM documents stay separate on purpose: the contract is what GIT HUD
  *recognises* (deliberately more permissive — it accepts the Professor
  variant), the skill is how a workspace gets *built*. Collapsing them would
  force one to lie.
