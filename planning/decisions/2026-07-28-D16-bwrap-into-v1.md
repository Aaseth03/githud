# D16 — bwrap is promoted out of "deferred" and into v1

**Date:** 2026-07-28 · **Status:** Committed
**Amends:** [D7](2026-07-28-D07-three-guardrail-layers.md) — Layer 2 is no longer
deferred, and Layer 3 is no longer assumed to exist.

## Context

D7 defined three guardrail layers and deferred Layer 2 (bwrap filesystem
scoping) "until something actually escapes." That deferral was only defensible
because Layer 3 — remote branch protection — was assumed to be the unbypassable
floor underneath everything.

Layer 3 turned out not to exist. Verified 2026-07-28 against this repo:

```
POST /repos/Aaseth03/githud/rulesets
→ 403 "Upgrade to GitHub Pro or make this repository public."
```

Rulesets and branch protection are unavailable on private repos on the free
plan.

## Decision

**bwrap moves into v1 as part of M4.** The agent subprocess runs inside a
bubblewrap sandbox with an explicit filesystem scope, alongside the PATH shim.

## Rationale

The deferral did not survive its own premise. D7 deferred Layer 2 *because*
Layer 3 was the floor; with Layer 3 gone, the argument for deferring Layer 2
went with it, and what remains is a PATH shim that D7 itself describes as
"bypassable via absolute path, so it is a guard, not a floor."

That is the exact failure this project's principle 3 exists to prevent: a guard
presented as a floor. D6 removes per-action approval and buys back the safety
with mechanism — if the mechanism is bypassable, D6 is resting on a promise
after all.

bwrap is the right replacement rather than a workaround:

- It is a **real OS-level floor**. Unlike the shim, it does not care what binary
  is invoked or by what path — a process cannot write outside its bind mounts.
- It is **already installed** — `bubblewrap 0.11.0` on this machine.
- It is **known territory, not research.** The vault has already proven a bwrap
  floor works (`AIOS/Memory/Topics/write-guardrail-hooks`), including its
  default-deny test approach.
- It **costs nothing** and requires no plan change at GitHub.

GitHub Pro remains worth buying separately to restore Layer 3 as designed, but
it is a **complement, not a substitute**: no remote rule stops a local
`rm -rf`, and Layer 3 only ever protected shared history.

## Consequences

- **M4 now ships three things**: the PATH shim, the bwrap scope, and the
  default-deny suite covering both. Ship on green only.
- The shim is demoted to what it always was — a fast, legible guard that gives
  good error messages. **The floor is bwrap.** Write the shim accordingly; do
  not let it carry weight it cannot hold.
- The v1 line grows by one item. This is the only scope increase accepted so
  far, and it is accepted because the alternative is shipping a trust model that
  does not hold.
- bwrap comes off the "deliberately deferred" list in `../milestones.md`.
- The sandbox scope itself needs specifying at M4: the project directory
  read-write, the toolchain read-only, `~/.ssh` and `~/.gitconfig` not mounted
  at all. Not decided here — that belongs in the M4 plan.

## Rejected alternatives

| Option | Why not |
|---|---|
| Make the repo public to get free rulesets | The project is private by intent |
| Accept the shim alone | A guard presented as a floor — the failure this design exists to avoid |
| GitHub Pro *instead of* bwrap | Only protects shared history; does nothing about local destruction |
